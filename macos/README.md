# B站 Mac 自定义角色使用教程

适用程序：SonicBilibili.mjs v1.1.0 | 教程修订：2026-10-27

请按顺序完成：**解压文件 → 进入脚本文件夹 → 检查环境 → 指定角色 → 确认角色 → 退出B站 → 启动角色模式。**

这里的“进入脚本”指在终端进入脚本所在的文件夹，**不用打开、编辑或替换JS代码**。角色素材由卖家提前处理；你只需要选择交付好的GIF。

## 开始前确认

- 你使用的是 **Mac电脑**。本程序不支持Windows、手机或平板。
- 已安装官方B站，应用位于 `/Applications/哔哩哔哩.app`，原本能正常播放视频。本机已验证版本为1.18.0，其他版本需另行确认。
- 终端能运行Node.js 22或更高版本；不会使用Node时先看第3步。
- 播放器顶部标签、Dock图标不会改变。角色显示在**视频播放器的进度条**附近。
- 本程序不需要安装Stylus、Tampermonkey、Codex或任何npm依赖。

## 第1步：解压并放好文件

将收到的ZIP完整解压，放到一个固定、可写的位置，例如“下载”或“文稿”。正式定制交付文件夹应包含：

```text
Sonic-Mac/
├── SonicBilibili.mjs   ← 程序，不用编辑
├── README.md          ← 本教程
└── character.gif      ← 卖家处理好的角色动画
```

若角色GIF是单独发来的，请先下载，再移入同一个 `Sonic-Mac` 文件夹。

**没有character.gif时先联系卖家补发。** 通用模板包只有程序和教程，不含你的定制角色；不要拿截图、JPG或改过后缀的文件冒充GIF。默认Sonic演示不等于已经设置好你的角色。

不要直接在压缩包中运行。不要改程序文件名，也不要把文件夹里的文件分散到不同位置。

## 第2步：让终端进入这个文件夹

1. 打开Mac的“终端”：可在聚焦搜索中输入“终端”后打开。
2. 在终端输入下面两个字符和一个空格：

```bash
cd 
```

3. **先不要按回车**，将Finder中的整个 `Sonic-Mac` 文件夹拖入终端。
4. 终端会填入文件夹路径，现在按回车。

你输入的完整一行会类似 `cd /Users/你的名字/Downloads/Sonic-Mac`，实际路径以你拖入的文件夹为准，不需要手工输入用户名。

输入：

```bash
ls SonicBilibili.mjs character.gif
```

**成功标志：** 终端列出这两个文件，且没有 `No such file or directory`。有错误先停下，检查是否进入了正确的解压文件夹、是否拿到了角色GIF。

后面所有命令都在这个终端、这个文件夹中运行。每个代码框输入完成后按一次回车，不要把解释文字也粘贴进去。

## 第3步：检查Node环境

输入：

```bash
node -v
```

**成功标志：** 显示 `v22...`、`v24...` 或更高版本。

若出现 `command not found: node`，从 [Node.js官网](https://nodejs.org/en/download)安装适合自己Mac芯片、仍受支持的22或更新版本。安装后关闭并重新打开终端，重新完成第2步，再检查版本。已有Node但低于22时也需要更新。

本教程不要求运行 `npm install`，也不需要给卖家账号密码。

## 第4步：指定交付好的角色

确认第2、3步通过后，输入：

```bash
node SonicBilibili.mjs character "./character.gif"
```

这条命令会读取同一文件夹里的 `character.gif`，检查并保存到本机。它不会上传图片，不会立即强制启动B站。

**成功标志：** 终端显示“GIF已在本机保存”，并给出尺寸、帧数。首次设置且未运行角色模式时，还会提示下次start时使用该角色。

如果出现格式、尺寸、帧数或文件损坏错误，停止并把完整错误发给卖家处理。**不要改程序限制、不要编辑代码，也不要只改图片后缀。**

### 如果GIF文件叫别的名字

优先请卖家统一命名为 `character.gif`。也可以改用选图框：

```bash
node SonicBilibili.mjs character
```

在弹出的Mac窗口里选择收到的GIF。取消选择会保持原角色不变。两种方式任选一种，不必都执行。

## 第5步：确认保存的是你的角色

输入：

```bash
node SonicBilibili.mjs character-info
```

**成功标志：** 输出包含：

```text
"source": "custom"
"name": "character.gif"
```

选了其他文件名时，name会显示那个名字。source为 `builtin` 表示仍是内置角色，请回第4步重新设置。

这一步只确认保存结果；还没有证明角色已在播放器中显示。不要把“保存成功”当作全部安装完成。

## 第6步：完整退出B站

保存需要保留的操作，在B站菜单中选择“退出”，或按：

```text
Command + Q
```

等待几秒。只关闭视频窗口、首页窗口或最小化窗口，不代表客户端已经退出。

这是为了让下一步从角色模式入口启动。程序不会为了安装而强制结束已有的播放。

## 第7步：启动B站角色模式

回到刚才的终端，输入：

```bash
node SonicBilibili.mjs start
```

**成功标志：** 终端显示“角色模式已启动”，官方B站自动打开。

然后：

1. 在客户端里打开一个普通视频，并等待加载完成。
2. 将鼠标移到播放器，查看原生进度条附近的角色。
3. 把鼠标移出播放器，等待控制栏收起；角色应转到底部半透明条。
4. 用原生进度条跳转，再观察角色位置是否随实际播放进度更新。

角色不会显示在首页推荐卡片或App顶部标签上。普通视频有确定时长后才能计算进度；直播不在本版支持范围内。

GIF自带的动作会循环播放。暂停视频时位置停止前进，但GIF动作仍可能继续。本版不会自动生成站姿或跑步帧。

启动成功后可以关闭终端，后台会继续服务本次角色会话。**关闭终端不会恢复默认，也不会删除角色。**

## 第8步：首次测试完，验证恢复普通模式

恢复会中断当前播放并重启B站，先结束需要保留的操作。

在原来的脚本目录输入：

```bash
node SonicBilibili.mjs restore
```

**成功标志：** 提示角色已移除，B站正常退出后从官方入口重新打开；再次打开视频时没有自定义角色。

恢复只停止这次角色模式，不会清除你保存的GIF。下次start仍会使用它。

首次使用建议完整完成这8步，确认“能用，也能恢复”，再作为日常使用方式。

## 以后每次使用，只做什么

### 继续使用已保存的角色

不用每次重新指定GIF，也不用每次调用Codex：

1. 打开终端，按第2步进入原来的 `Sonic-Mac` 文件夹。
2. 正常退出B站，等几秒。
3. 输入：

```bash
node SonicBilibili.mjs start
```

### 想正常看B站、不显示角色

先执行restore；或者完整退出角色模式的B站，再点击官方图标打开。

**角色实例仍在运行时，点击官方图标通常只是返回同一个实例，不能靠换入口即时切换模式。**

### 想换另一只角色

把新GIF发给卖家处理，收到成品后回到第4、5步重新指定和确认。仅把新文件放进文件夹，不会自动替换已保存角色。

程序支持刷新正在运行的本包会话；如果提示“素材已保存，但会话刷新未完成”，先restore，再start。不要把“已保存”理解为“当前画面已更新”。

## 出问题时先看这里

| 现象 | 该怎么做 |
| --- | --- |
| `node: command not found` | 完成第3步安装／检查Node，重新打开终端再进入文件夹 |
| `Cannot find module ...SonicBilibili.mjs` | 当前目录不对，或程序被改名；重做第2步 |
| `No such file or directory`／找不到character.gif | 确认角色文件已下载并放进同一文件夹，留意不要变成character.gif.gif |
| GIF格式、尺寸、帧数错误 | 发完整错误给卖家；不要改后缀或绕过检查 |
| 仍显示默认Sonic | 第5步检查source是否custom；确认在正确文件夹指定了新GIF |
| 提示B站仍在运行 | Command+Q，等几秒再start；只关窗口不够 |
| 首页没有角色 | 打开普通视频详情窗口后再检查，这是正常的显示范围 |
| 图片有白色方块／背景不透明 | 素材背景需要由卖家重新处理，不是客户端安装失败；发原GIF与效果截图 |
| 关闭终端后角色还在 | 属于预期；执行restore才会恢复普通模式 |
| 换电脑／换文件夹后角色没了 | 原来的角色保存在旧文件夹的运行目录中；用卖家成品GIF重新完成第4步 |
| 升级B站后不显示 | 可能需要客户端版本适配；先恢复普通模式并反馈版本 |

### 能打开客户端，但角色仍不显示

在同一目录输入：

```bash
node SonicBilibili.mjs status
```

- `state: active`、`image: loaded`：程序已识别播放器并解码角色，再检查截图中的位置和模式。
- `mode: native-track`：角色在原生进度条位置。
- `mode: idle-bottom`：角色在隐藏控制栏后的底部条。
- “等待打开一个视频”或 `waiting-player`：没有可见播放器，正常打开一个视频再试。
- `waiting-duration`：等待视频元数据加载；直播等无有限总时长的内容不支持。
- `error`：保留message字段，停止反复启动，先恢复并联系卖家。

反馈时提供：Mac系统版本、B站版本、失败步骤编号、完整错误文字、status结果及播放器底部截图。遮住账号和私人内容，不发送密码、验证码、Cookie或未经检查的完整日志。

## 其他命令：初次安装不用执行

下面两条容易混淆：

```bash
# 清除自定义选择，改回内置Sonic；角色功能仍可继续使用
node SonicBilibili.mjs character-reset

# 完全结束角色模式，重启回普通B站；保留已保存的角色
node SonicBilibili.mjs restore
```

程序内容检查：

```bash
node SonicBilibili.mjs self-check
```

自检不启动B站，也不代表已经完成真实视频显示验收。

## 本机保存与卸载

程序会在脚本旁生成隐藏的 `.sonic-runtime` 文件夹，保存本机角色和会话记录。不要手工修改它。原始GIF被移动后，已保存角色仍可使用；但移动／删除整个脚本文件夹前应先恢复默认。

卸载：先执行restore，确认普通模式正常，再删除本文件夹。不会删除B站官方客户端、登录数据或聊天资料。

本方案临时使用仅监听127.0.0.1的本机调试入口，不修改官方安装包。完整退出对应客户端才会关闭该调试会话；不要将端口转发给其他设备。系统全屏、迷你模式、其他版本尚需分别验收。

## 卖家发货前检查（客户可跳过）

### 建议采用的服务流程

客户发原GIF → 你处理透明背景和裁剪 → 检查动画帧与速度 → 以character.gif交付 → 客户按第1-8步操作。

客户不需要自己抠图、调用Codex或修改JS。复杂素材处理是否包含在价格内，售前先约定。

### 每位客户的正式交付最少3个文件

```text
Sonic-Mac/
├── SonicBilibili.mjs
├── README.md
└── character.gif
```

通用模板下载包只有前两个文件。发给定制客户前，另放入你处理好的 `character.gif`，再压缩整个文件夹。

不要发送你自己的 `.sonic-runtime`、旧包 `.runtime`、日志、进程记录或私人测试截图。不要只给客户一份JS却没有解释环境与恢复方法。

### 素材检查由你完成

- 真实GIF87a/89a，不是改名的其他格式；角色素材具备相应使用权。
- 不超过2MiB；单边不超过2048像素，总画布不超过400万像素。
- 最多300帧；画布像素乘帧数不超过1亿。
- 检查透明背景，尤其白色衣服、手套、眼睛等不能被误删。
- 确认处理后帧顺序、播放时长、循环与裁剪范围正常。
- 显示会保持比例缩小到48×48范围内，不放大更小素材；先确认小尺寸下仍清楚。
- 结构校验不等于所有压缩数据均可解码；还要检查实际image为loaded。

### 验证范围必须写实

原多文件实现已在本机官方Mac客户端1.18.0验证真实Sonic显示、显隐切换和恢复。单文件版GIF导入、持久保存、拒绝异常素材和模拟播放器解码已检查；不代表已在每位客户的系统、选图框和播放器模式中通过。

升级：先用原版本restore，再替换程序，保留客户自己的运行目录，不把你的运行目录覆盖给客户。新版本网页／客户端结构变化可能需要维护，不承诺永久兼容。
